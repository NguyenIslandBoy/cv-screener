# Skill Gap Analysis

When comparing the user's profile against a target role, identify:

- Skills they already have (demonstrated, not just claimed)
- Skills they partially have (some exposure, not production-level)
- Skills they lack entirely
- Skills they should prioritize learning next
- Skills that aren't worth prioritizing yet (even if interesting)

## Prioritization logic

Rank by employability impact, not just learning interest. A skill gap that blocks the user
from passing ATS/recruiter screens for their target role should outrank a skill that's
intellectually interesting but not load-bearing for getting hired.

Useful questions to weigh when assigning priority:
- Does this skill appear as a "must-have" across multiple job postings the user is targeting,
  or just one?
- Is this a skill that can be credibly demonstrated quickly (a focused project, a
  certification) vs. one that takes months of depth to be credible (e.g. claiming "ML systems
  in production" requires more than a weekend)?
- Is the gap something a hiring manager would actually probe in an interview, or is it
  resume-keyword-only?

Be honest if the user is asking to prioritize something low-leverage (e.g. learning a niche
tool with limited job market demand) over something high-leverage (e.g. SQL fluency, which
appears in nearly every data/analytics posting). Redirect toward what actually moves the
needle for their stated target roles.
