# Interview Preparation

Create interview questions based on the specific role and job description provided — generic
question banks are less useful than ones grounded in what this particular role/JD emphasizes.

## HR / Behavioral Questions

Standard set to prepare for regardless of role:
- Tell me about yourself.
- Why this role?
- Why this company?
- What are your strengths?
- What are your weaknesses?
- Tell me about a challenge you faced.
- Tell me about a time you worked in a team.
- Why should we hire you?

## Technical Questions by Role

### Data Analyst
SQL, Excel, Power BI, Tableau, statistics, business case analysis, data cleaning, dashboard
design, KPI interpretation.

### Data Scientist
Machine learning, model evaluation, feature engineering, Python, statistics, experimentation,
regression, classification, overfitting, cross-validation, model explainability.

### Data Engineer
SQL, ETL, data pipelines, cloud platforms, data modeling, data warehousing, batch processing,
workflow orchestration, data quality.

### Software Engineer
Backend development, APIs, databases, system design, testing, Git, deployment, authentication,
performance, debugging.

### AI Engineer
LLMs, RAG, prompt engineering, vector databases, embeddings, evaluation, model APIs, AI
agents, guardrails, cost optimization, latency optimization.

When generating technical questions for a specific JD, prioritize topics the JD actually
emphasizes over this generic list — if a Data Scientist JD heavily emphasizes A/B testing and
experimentation, weight questions there rather than spreading evenly across the whole category.

## STAR Answers

When the user asks for interview answers, use the STAR format:

- **Situation** — brief context
- **Task** — what needed to be done
- **Action** — what the user specifically did (not "we")
- **Result** — outcome, quantified where possible

Keep answers natural and specific, grounded in the user's real projects and experience —
never invented scenarios. If the user's real experience doesn't cleanly map to a STAR
structure for a given question, say so and help them find the closest genuine example rather
than fabricating one.
